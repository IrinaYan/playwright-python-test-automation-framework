## Overview

This project is a UI test automation framework built to automate end-to-end
test scenarios for the Automation Exercise practice website.[Automation Exercise](https://automationexercise.com/)

This framework is built with Python, Playwright, and Pytest, following the Page Object Model (POM) design pattern. 

Allure results, logs, and screenshots are preserved after test execution, including failed runs, and the generated Allure report is published to GitHub Pages.


The project demonstrates:

- Python-based Playwright UI automation
- Pytest test execution
- Page Object Model architecture
- Reusable Base Page
- Custom Pytest fixtures
- Pytest hooks
- Test data management and dynamic test data generation
- Environment configuration with `.env`
- Failure screenshots
- Logging and log management
- Allure test reporting
- Allure environment information
- Cross-browser testing
- Test retry mechanism using `pytest-rerunfailures` for flaky tests
- Test isolation using independent fixtures and test data
- Test selection using Pytest markers
- Parallel test execution using `pytest-xdist`
- Docker & Containerization
- CI/CD automation using GitHub Actions
- Automatic Allure report deployment to GitHub Pages / Public Allure report

## Framework Architecture

The framework follows the **Page Object Model (POM)** design pattern.

The main responsibilities are separated into:

- **Page Objects** — contain page locators and reusable page actions
- **Tests** — contain test scenarios and assertions
- **Test Data** — stores reusable test data separately from test logic and generates unique data dynamically when required to prevent conflicts
- **Utils** — contains reusable utility modules:
  - `config.py` — loads and provides access to environment-specific configuration from `.env`
  - `logger.py` — configures timestamped file and console logging for test execution
- **Reports** — provides test execution results through Allure
- **Logs** — stores timestamped test execution log files generated by the logging utility
- **Screenshots** — stores screenshots automatically captured on test failure and attached to the Allure report
- **Fixtures** — `conftest.py` provides reusable Page Object instances, manages test data and user registration workflows, and handles automatic failure screenshots with Allure attachments. The Playwright `page` fixture is used by tests to interact with the browser.

## Prerequisites

Before running the tests, make sure the following are installed:

- **Python 3.12+**
- **Git**
- **Java** — required by Allure Commandline
- **Allure Commandline**
- **Docker** — optional, required only for containerized test execution

Project dependencies can be installed from `requirements.txt`.



## Installation

    1. Clone the repository

        ```bash
        git clone <repository-url>
        cd playwright-python-test-automation-framework
        ```

    2. Create a virtual environment

        Windows: python -m venv venv
        macOS / Linux: python3 -m venv venv


    3. Activate the virtual environment

        Windows: venv\Scripts\activate
        macOS/Linux: source venv/bin/activate


    4. Install Python dependencies

        pip install -r requirements.txt


    5. Install Playwright browsers

        playwright install




## Configuration

- Create a .env file in the project root and add the required environment variables.
- You can use `.env.example` as a template.
- Do not commit .env to the repository if it contains sensitive information.
- `.env` values are loaded in `utils/config.py` using `python-dotenv`.




## Running Tests

Run the entire test suite:

    ```bash
    - Run all tests: pytest
    - Run tests with verbose output: `pytest -v`
    - Run a specific test file: `pytest tests/test_login.py`
    - Run a specific test: `pytest tests/test_login.py::test_valid_login`
    - Run tests in headed mode: `pytest --headed`
    - Run tests in parallel: `pytest -n 2` - runs tests using two parallel workers
    - Run tests in parallel: `pytest -n auto` - automatically selectes number of workers
    - Run tests in cross-browser: `pytest --browser chromium --browser firefox --browser webkit`
    - Run tests up to 2 additional times: `pytest --reruns 2` for intermittent/flaky failures
    - Run tests marked with @pytest.mark.smoke: `pytest -m smoke`
    - Run tests marked with @pytest.mark.regression: `pytest -m regression`
    ```

## Docker
The test automation framework can be executed inside a Docker container to provide a consistent, isolated and reproducible test execution environment.

Make sure the following are installed: 
- Docker Desktop


Verify the Docker installation:
- docker --version


### Build the Docker Image

From the project root directory, run:
- docker build -t playwright-tests:1.0 .


### Run Tests in a Docker Container

After building the image, run the test suite inside a container:
- Run tests: `docker run --rm playwright-tests:1.0`
- Run tests in parallel and pass .env values to the container: `docker run --rm --env-file .env playwright-tests:1.0 pytest -n 2`
- Run tests passing .env values to the container: `docker run --rm --env-file .env playwright-tests:1.0`


### Run Specific Tests

To execute a specific test file:
- docker run --rm playwright-tests pytest tests/test_login.py -v


To execute tests in parallel:
- docker run --rm playwright-tests pytest -n 2 -v


### Test Artifacts

The framework generates test artifacts such as: 

- Screenshots for failed tests
- Log files
- Allure test results



### Preserve Test Artifacts from Docker

Run the test suite inside the Docker container and preserve test artifacts on the host machine:

docker run --rm --env-file .env `
  -v "${PWD}\screenshots:/app/screenshots" `
  -v "${PWD}\logs:/app/logs" `
  -v "${PWD}\allure-results:/app/allure-results" `
  playwright-tests:1.0 pytest --alluredir=allure-results



This command:

- Loads environment variables from .env
- Runs the tests inside the Docker container
- Mounts screenshots/, logs/, and allure-results/ so artifacts remain available after the container is removed
- Generates Allure test results in allure-results/
- Automatically removes the container after execution with --rm


To view the Allure report after the test run:
- allure serve allure-results



### Docker Compose

The project also includes a compose.yaml file that defines how the test container is built and executed.

Docker Compose is currently configured with a single tests service because the framework does not yet require additional services such as a database or API container.
Docker Compose is currently used to simplify and standardize containerized test execution. As the framework evolves, additional services such as a database or mock API can be added to the Compose configuration when required.

The Compose configuration:

- Builds the test image using the project Dockerfile
- Loads environment variables from .env
- Mounts test artifact directories from the host machine
- Runs the Pytest test suite
- Preserves screenshots, logs, and Allure results after container execution


### Running Tests with Docker Compose

To build the Docker image and run the test suite:
- docker compose up --build

For subsequent test runs, when rebuilding the image is not required:
- docker compose up

Viewing the Allure Report

After the test execution is complete, generate and open the Allure report locally:
- allure serve allure-results








## CI/CD with GitHub Actions

The project uses GitHub Actions to automatically build the Docker image and execute the Playwright test suite 
in a consistent CI environment.
     

The workflow is triggered on:

- Pushes to the repository
- Pull requests

### CI Pipeline

The GitHub Actions workflow performs the following steps:

1. Checks out the repository
2. Creates the `.env` file using GitHub Secrets
3. Verifies Docker and Docker Compose
4. Builds the Docker image
5. Runs the Playwright test suite using Docker Compose
6. Collects screenshots generated for failed tests
7. Collects test execution logs
8. Collects Allure test results
9. Generates the Allure HTML report
10. Publishes the Allure report to GitHub Pages

Sensitive configuration values such as `BASE_URL` and `PASSWORD` are stored securely as GitHub Actions Secrets and are not committed to the repository.
